📄 [미니 프로젝트 계획서] : 고객 관리 시스템 (CRM)

1. 프로젝트 개요
    - 프로젝트명: 객체지향 기반 고객 관리 시스템 (CRM) 미니 프로젝트
    - 목적: Python의 핵심 문법(클래스 상속, 예외 처리, 모듈 분리, 콘솔 I/O)을 활용한 실무형 데이터 관리 시스템 구현
    - 데이터 저장 방식: 메모리 기반(List) 임시 저장 (프로그램 종료 시 초기화)


2. 주요 기능 (요구사항 매핑)
    - 고객 등록: 일반 고객 및 VIP 고객 분리 등록 (연락처 중복 검사)
    - 고객 조회: 전체 고객 명단, VIP 고객 명단, 특정 포인트 이상 보유 고객 검색
    - 정보 수정 및 활동: 고객 연락처 수정, 제품 구매 시 등급별 포인트 자동 적립 (일반 1%, VIP 5%)
    - 고객 탈퇴: 고객 ID 기반 데이터 삭제


3. 프로그램 구조 (모듈화)
    - models.py: 고객 도메인 데이터 클래스 및 사용자 정의 예외 클래스 정의
    - crm_manager.py: 리스트(List)를 기반으로 고객 데이터를 등록/조회/수정/삭제하는 비즈니스 로직 클래스
    - main.py: while 루프를 통한 사용자 CLI(명령줄 인터페이스) 메뉴 제공 및 시스템 실행


4. 협업 시 각 역할 (과제 제출용)
    - 본인 (기획자 및 리뷰어):
        - 프로젝트의 요구사항 정의 및 전체 아키텍처 설계
        - AI가 작성한 코드의 문법적 오류 검토 및 요구사항 충족 여부 테스트
        - __str__ 출력 형식 등 사용자 경험(UX) 관점의 텍스트 수정 및 디버깅
    - AI (개발 지원):
        - 기획안을 바탕으로 한 Python 소스 코드(초안) 구현
        - 클래스 상속 및 커스텀 예외 처리 등 핵심 문법 로직 작성


5. 구현 현황 (Done)
    - [models.py](models.py)
        - 커스텀 예외 `DuplicateContactError`, `CustomerNotFoundError` 정의
        - 부모 클래스 `Customer` (ID, 이름, 연락처, 누적 포인트) 및 공통 `__str__` 오버라이딩
        - 자식 클래스 `NormalCustomer`(구매액의 1% 적립), `VIPCustomer`(구매액의 5% 적립 + 전담 매니저 이름 속성)
        - 각 자식 클래스별 `__str__` 오버라이딩으로 등급/매니저 정보까지 일관된 형식으로 출력
    - [crm_manager.py](crm_manager.py)
        - `CRMManager`가 `self.customers` 리스트에 모든 데이터를 메모리 상에서만 보관 (파일/DB 미사용)
        - 고객 등록 시 연락처 중복 검사 → 중복 시 `DuplicateContactError` 발생
        - 전체 고객 조회 / VIP 고객만 조회 / 특정 포인트 이상 고객 검색
        - ID 기준 연락처 수정, 상품 구매(등급별 포인트 자동 적립), 고객 탈퇴 — 모두 대상이 없으면 `CustomerNotFoundError` 발생
        - 등록 시 내부 카운터로 ID를 자동 발급하여 ID 중복 문제를 원천 차단
        - **[신규] 입력값 유효성 검사**: 구매 금액(`purchase`)과 검색 포인트(`find_by_min_points`)에 음수가 들어오면 `ValueError` 발생
        - **[신규] 단일 고객 상세 조회**: `get_customer_by_id()`로 ID 기준 고객 1명을 조회 (없으면 `CustomerNotFoundError`)
        - **[신규] 연락처 외 정보 수정**: `update_name()`(이름 수정), `change_grade()`(일반↔VIP 등급 전환), `update_manager()`(VIP 전담 매니저 재배정)를 추가했습니다. `change_grade()`는 같은 ID/연락처/포인트를 유지한 채 객체만 교체합니다
        - **[신규] 연락처 형식 검증**: `CONTACT_PATTERN` 정규식(`0xx-xxx(x)-xxxx`)으로 등록/수정 시 형식을 검사, 형식이 잘못되면 `ValueError` 발생
    - [main.py](main.py)
        - `while` 루프 기반 1~9번 메뉴로 위 기능 전체를 대화형 콘솔에서 실행 가능
        - 예외(`DuplicateContactError`, `CustomerNotFoundError`, `ValueError`)를 각 메뉴에서 try/except로 처리하여 사용자에게 안내 메시지 출력
        - **[신규]** 5번 "고객 상세 조회(ID)", 6번 "고객 정보 수정" 메뉴 추가 (6번은 이름/연락처/등급 전환/VIP 매니저 변경을 선택하는 하위 메뉴로 구성)
    - 수동 테스트: 등록·조회·수정·구매·탈퇴 전 기능과 주요 예외 케이스(중복/형식 오류/음수 등)를 콘솔에서 순차 실행하여 정상 동작을 확인했습니다
