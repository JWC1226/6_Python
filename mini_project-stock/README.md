# 재고 관리 프로그램 (mini_project-stock)
    객체지향(상속·다형성)과 커스텀 예외 처리를 연습하기 위한 콘솔 기반 재고 관리 프로그램입니다.
    `models.py` / `inventory.py` / `main.py` 세 파일로 구성되어 있습니다.
===========================================================================================

## 구현된 기능
1. **객체지향 및 상속**
  - 공통 속성(상품 코드, 품명, 단가, 재고수량)을 가진 부모 클래스 `Product`

  - `Product`를 상속받는 `NormalProduct`(위험물 여부 `is_hazardous` 추가)

  - `Product`를 상속받는 `FreshProduct`(유통기한 `expiration_date` 추가)
------------------------------------------------------------------------------------------
2. **예외 처리**
  - `OutOfStockError`: 출고 수량이 현재 재고를 초과할 때 발생
  
  - `ProductNotFoundError`: 존재하지 않는 상품 코드를 조회/수정/삭제할 때 발생
------------------------------------------------------------------------------------------
3. **데이터 저장**
  - 파일/DB 없이 `InventoryManager.products` 리스트에만 데이터를 유지 (프로그램 종료 시 초기화됨)
------------------------------------------------------------------------------------------
4. **다형성 및 출력 일관성**
  - `Product`, `NormalProduct`, `FreshProduct` 모두 `__str__()` 오버라이딩으로 동일한 형식으로 출력

  - `get_price()` 공통 인터페이스 제공, `FreshProduct`는 이를 오버라이딩
------------------------------------------------------------------------------------------
5. **신선 식품 할인 로직**
  - `FreshProduct.get_price()`는 `datetime.date`로 오늘 날짜와 유통기한의 차이(`.days`)를 계산하여,
    남은 일수가 3일 이하(이미 지난 경우 포함)면 단가의 50%를 반환
------------------------------------------------------------------------------------------
6. **관리자 기능 (`InventoryManager`)**
  - 신규 상품 등록 (`add_product`, 코드 중복 시 `ValueError`로 방지)

  - 전체 재고 조회 (`get_all_products`)
  
  - 긴급 발주 목록 조회 (`get_urgent_reorder_list`, 재고 10개 미만)
  
  - 전체 재고 총 금액 확인 (`get_total_inventory_value`, `get_price() * stock` 합산)
  
  - 입고 처리 (`stock_in`)
  
  - 출고 처리 (`stock_out`, 재고 부족 시 `OutOfStockError`)
  
  - 상품 단가 수정 (`update_price`, 코드 없을 시 `ProductNotFoundError`)
  
  - 단종 품목 삭제 (`delete_product`, 코드 없을 시 `ProductNotFoundError`)
------------------------------------------------------------------------------------------
7. **UI 로직 (`main.py`)**
  - `while` 루프 기반 대화형 콘솔 메뉴 (0~8번)
  
  - 숫자/날짜 입력 형식 오류에 대한 재입력 처리
  
  - `OutOfStockError`, `ProductNotFoundError`를 각 메뉴에서 개별적으로 안내
===========================================================================================

## 구현되지 않은 부분 / 제한 사항
1. **데이터 영속성 없음**: 요구사항에 따라 의도적으로 파일/DB 저장을 하지 않으므로,
    프로그램을 재실행하면 등록한 상품이 모두 사라집니다.

2. **입력값 유효성 검사가 최소한으로만 되어 있음**: 단가·재고수량·입출고 수량에 음수를 입력해도 별도로 막지 않습니다.
    상품 코드 형식(자릿수, 접두어 등)에 대한 검증도 없습니다.

3. **상품 코드 중복 등록 방지는 커스텀 예외가 아닌 `ValueError`로 처리**: 요구사항에 명시된 2개
    (`OutOfStockError`, `ProductNotFoundError`) 외의 추가 예외 클래스는 만들지 않았습니다.

4. **상품 검색/정렬 기능 없음**: 상품명 검색, 가격순·재고순 정렬 등은 요구사항에 없어 구현하지 않았습니다.

5. **동시성/다중 사용자 고려 없음**: 단일 프로세스, 단일 사용자 콘솔 환경만 가정합니다.

## 학습 포인트
1. **datetime 모듈 활용 확인**: `models.py`의 `FreshProduct` 클래스 안에서 유통기한과 오늘 날짜를 비교하는 로직이 어떻게 구현되었는지
    확인해 보세요. 날짜 차이(days)를 계산하는 방법은 파이썬에서 매우 자주 쓰입니다.

2. **다형성(Polymorphism)의 진가**: 전체 재고 총 금액을 계산할 때, `inventory.py` 안에서 굳이 '이게 신선식품인지 일반품목인지'
    구분하지 않고 그저 `product.get_price() * product.stock` 형태로 깔끔하게 계산하는 부분을 눈여겨보세요.
    이것이 바로 객체지향에서 자식 클래스가 메서드를 덮어쓰기(오버라이딩)하여 얻는 가장 큰 장점입니다.

3. **재고 차감 로직**: 출고 시 `product.stock -= amount`를 하기 전에 if문으로 재고가 충분한지 검사하고
    `raise OutOfStockError`를 던지는 예외 처리 흐름을 살펴보세요.
